# Pocket Web for Rokid Glasses

Экспериментальный Android-браузер для Rokid Glasses с зелёным монохромным экраном (RV101/Glass3). Работает **на самих очках**, без телефонного приложения. Внешний Rokid SDK не требуется: приложение использует системный WebView и стандартные события тачпада Android.

## Что умеет версия 0.2

- Открывает произвольный HTTPS-адрес или поисковый запрос. На стартовом экране есть Google, Wikipedia, GitHub, YouTube, Telegram Web, ChatGPT, DeepSeek и Qwen.
- Собирает видимые заголовки, абзацы, ссылки, кнопки и поля ввода в крупные карточки с чёрным фоном и зелёным текстом.
- Оставляет сайт и его сеанс в том же WebView: клик по карточке действует на исходный элемент страницы. Изменения в одностраничном приложении подхватываются с небольшой задержкой.
- Позволяет переключиться на исходную страницу и перемещать фокус между её элементами.
- Даёт вводить адрес и текст в формы экранной клавиатурой: свайп выбирает группу, тап открывает её, следующий свайп выбирает символ, тап вводит его. Есть пробел, удаление, «Готово» и «Отправить».
- По желанию включает управление головой через датчик `GAME_ROTATION_VECTOR` (либо `ROTATION_VECTOR`, если первого нет): взгляд вправо/влево листает карточки, наклон головы вниз с удержанием выбирает. Тачпад работает параллельно. Включение и центрирование работают и при касании пункта меню.

## Управление

| Очки | Карточки | Клавиатура | Исходная страница |
| --- | --- | --- | --- |
| Свайп вперёд/назад | Следующая/предыдущая карточка | Выбор группы или символа | Следующий/предыдущий элемент |
| Один тап | Открыть выбранное | Подтвердить | Нажать элемент |
| Назад/двойной тап, если система выдаёт `BACK` | Предыдущая страница | Назад к группам/странице | Вернуться к карточкам |
| Голова вправо/влево после включения | Следующая/предыдущая карточка | Выбор символа | Следующий/предыдущий элемент |
| Наклон головы вниз с удержанием | Открыть карточку | Подтвердить | Нажать элемент |

Карточки меню находятся в начале списка. Для головы выбери «Голова: включить»: приложение попросит нажать тачпад, глядя прямо, повернув голову вправо, снова прямо, наклонив вниз и снова прямо. Так оно узнает оси и направление датчика именно на твоей прошивке. Повернись примерно на 18° и удержи 0,2 секунды для одного шага; верни голову в центр перед следующим. Наклони вниз примерно на 14° и удержи 0,4 секунды для выбора. «Центр головы» сбрасывает нейтральную позу; «Голова: выключить» отключает датчик. Аппаратная клавиша Menu переключает исходную страницу; долгое нажатие остаётся системной функцией Rokid.

Во время калибровки приложение проверяет, что голова вернулась примерно в центр. Если повернуться или кивнуть недостаточно, шаг будет предложено повторить. Настройка головы действует до закрытия приложения; после нового запуска её надо включить заново.

## Сборка APK

1. Откройте папку проекта в Android Studio с Android SDK Platform 35 и JDK 17 либо установите Gradle 8.7 и Android SDK.
2. Выполните `gradle assembleDebug` из корня проекта.
3. Файл будет в `app/build/outputs/apk/debug/app-debug.apk`.
4. Включите режим разработчика/ADB на очках, подключите **кабель разработчика**, затем `adb install -r app/build/outputs/apk/debug/app-debug.apk`.

В проекте также есть GitHub Actions workflow: после загрузки проекта в репозиторий команда `Build Android APK` собирает отладочный APK как артефакт. APK не подписан ключом для публикации, но debug-сборка устанавливается через ADB.

## Реальные пределы адаптации

Карточный режим подходит для чтения и простых ссылок/форм. Он не превращает автоматически в удобный интерфейс карты, видеоплеер, Canvas, сложный редактор или сайт, интерфейс которого находится внутри недоступного iframe. Для них служит режим исходной страницы. Сайты могут запрещать вход через встроенный WebView, а нажатие DOM-элемента из карточки может не сработать там, где браузер требует доверенный физический жест. Загрузка файлов, всплывающие окна, камера и микрофон не реализованы. HTTP без TLS отключён.

Это прототип для тестирования на конкретной прошивке очков. Направление свайпа и событие двойного тапа зависят от системной раскладки; при несовпадении достаточно поменять сопоставление в `MainActivity.dispatchKeyEvent`. Если прошивка не предоставляет ни `GAME_ROTATION_VECTOR`, ни `ROTATION_VECTOR`, головной режим недоступен и тачпад продолжает работать. При ходьбе головой лучше не управлять: режим специально включается вручную, имеет пороги, задержку и требует возврата к центру. Для пригодного ежедневного использования стоит испытать 3–5 нужных сервисов и добавить точечные правила для их интерфейсов.

## Проверка интерфейса

`tests/smoke.cjs` проверяет извлечение содержимого, обновление DOM, ввод и переключение режима в Chromium на экране 480×640. Для запуска нужны Node.js, `playwright` и установленный браузер Chromium. Команда: `node tests/smoke.cjs`.

Детектор жестов проверяется без Android SDK: `mkdir -p /tmp/rokid-test && javac -d /tmp/rokid-test app/src/main/java/dev/rokid/pocketweb/HeadGestureDetector.java tests/HeadGestureDetectorTest.java && java -cp /tmp/rokid-test dev.rokid.pocketweb.HeadGestureDetectorTest`. В урезанной JDK без команды `javac` можно вызвать `java com.sun.tools.javac.Main` с теми же аргументами.

## Основа и безопасность

Разработано с нуля, без копирования чужого кода. Ориентир по аппаратным событиям — [официальная документация Rokid](https://x-docs.rokid.com/docs/%E4%BB%A3%E7%A0%81%E7%A4%BA%E4%BE%8B/50-system/01-%E6%8C%89%E9%94%AE%E4%B8%8E%E4%BE%A7%E8%BE%B9%E8%A7%A6%E6%8E%A7.html). У приложения нет JavaScript-интерфейса с доступом к Android, а локальные файлы WebView закрыты. Cookies и данные сайтов хранятся в профиле самого приложения.
